# 0.3.4：通知呈现与原生解锁交接

本轮依据用户提供的两张截图及目标 SystemUI 实现修正。截图显示媒体底板消失、通知文字模糊、时钟与景深布局不一致；代码中确认的缺陷及修正如下。

| 问题 | 确认的代码路径 | 新行为 |
| --- | --- | --- |
| 卡片/媒体底板消失 | 只拦截原生 apply，后续 clear 可以清掉模块仍需要的材质 | 同时跟踪 apply 与 clear；呈现期间保留当前材质，结束后按最新原生意图恢复，已经清除的材质不会复活 |
| 只能看到部分通知 | 锁屏数量上限、堆叠模式被固定带入通知中心 | 仅呈现期间使用原生 LIST 模式和无限制数量；实际锁屏设置不改，原生通知列表负责滚动、通知操作和行高 |
| 通知页内部上划受阻 | 整页展开入口抢占可滚动列表 | 完整呈现时列表内的纵向滑动交给原生列表；时钟/空白区域仍控制整页运动 |
| 时钟与景深错位 | 只保留视图属性，原生通知页仍可重新布局锁屏控件 | 保留锁屏 chrome 的原生布局边界，时间数据继续更新；退出立即恢复最新原生布局，通知行不冻结 |
| 收起闪过全屏模糊 | 释放区域模糊时恢复了旧的全窗口模糊半径；静止展开页 hide 又触发一次原生动画 | 隐藏时明确清零全窗口和壁纸模糊，通过同一收起完成入口交还原生生命周期；认证/旋转恢复原生状态 |

## 锁屏到桌面改用原生交接

用户明确允许换一种联动方式。本版保留跟手内容位移、Flyme 弹簧参数、取消/反向/接手、原生认证、景深原有层级以及澎湃原生模糊。锁屏壁纸和景深不再被镜像或平移，不再提前准备桌面/应用窗口、切换 wallpaper token 或退役锁屏源。

拖动期间显示原生锁屏壁纸，不预览应用/桌面。接受释放后先清理本模块拥有的视觉状态，再调用原生认证与退出入口；桌面和应用窗口绘制、壁纸切换及桌面动画由系统统一处理。这是本轮的明确取舍，不称为实时透出或完整 Flyme 桌面过渡。

当前 SystemUI 不创建 NativeSceneChannel，不调用旧场景就绪等待或强制窗口可见路径。旧 system_server 兼容版本保持空闲，不需要为了本版重启手机；未来加载本版的 system_server 不注册旧场景 Hook。旧研究代码保留在源码内，编译产物审计核对它不在当前入口中实例化。

## 验证边界

核心回归覆盖材质原生意图、迟到 clear、通知数量/模式更新及单次原生解锁交接；模拟器验证布局保留与释放、通知呈现绑定、管理器等。目标 DEX 核对原生 LIST、列表上限接口及其余适配签名；编译产物检查无旧窗口准备/镜像调用。

这些检查不能证明手机画面已经没有闪烁，也不能证明手机实际通知滚动与全部材质已经通过验收。交付报告分别记录安装、加载与用户视觉验收。不录手机画面、不注入触摸、不要求反复复现。横屏继续使用原生通知栏，控制中心保持原有逻辑。作用域不增加，不 Hook Home 或普通应用。
