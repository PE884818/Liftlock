# 0.2.22：桌面直接使用原生壁纸，交回原生恢复

0.2.21 已实际加载，用户反馈桌面不出现、像被壁纸遮住。保存的 HOME 失败回执为 `phase=HANDOFF / backdrop=true / blended=false / ready=false / activity=STOPPED / windowVis=4 / drawn=false`。这证明壁纸兜底就绪而桌面主窗口没有开始有效绘制，无法只凭它断言手机桌面线程已经死锁。

读取现场时已返回普通应用，APP 已有新帧、有效 fence 和 `NATIVE_OWNED`，随后框架会话已结束。没有为获取桌面现场强制切回桌面，没有手机像素采集或触摸注入。

## 撤销桌面上方的不透明兜底

返回 HOME 且实际原生 HOME 壁纸引擎已绘制、容器和祖先层可见时，`ServerSceneCover.useNativeHome` 使用现有原生壁纸。它只撤销自己的保护层／兜底镜像，不复制一张壁纸放在桌面图标之上。原生壁纸的句柄借用而不释放，层级、透明度和父层不由覆盖助手改写。

返回 APP 且真实首帧尚未就绪时才创建临时实时桌面壁纸兜底。APP 已经就绪则不再分配新的兜底。跨返回目标或认证失效时清掉 HOME 直通状态并恢复对应保护；预览首帧仍独立验证，壁纸显示不算应用已绘制。

## 原生接管与预览首帧分开

代码审查确认原先 `shouldResumeActivity` 限制只核对瞬时 `isKeyguardGoingAway`。该标志清零后，即使原生已解锁，旧模块仍可能再次拒绝原生恢复。这是明确的代码错误，但尚不能仅凭保存的 HOME 行断言它解释全部失败。新版限制只在原生仍显示且仍锁定、并非正在退出、并非显式准备时成立。

有效上滑、原生认证已开始、原生 keyguard 已通知隐藏且锁屏收起帧存在时，UI 将这个收起帧交给退场所有者，不再以缺少预览 fence 阻断原生隐藏证明的提交。

框架保留独立的原生接管回执：原生不再显示／锁定／退出中，锁屏前景隐藏帧已提交，目标已 RESUMED、主窗口已获得原生焦点、原生已绘制并可见、祖先层可见。取得这些条件后退出自己的准备干预、撤销覆盖，并在覆盖事务提交后通知 UI 释放。这个回执用于结束模块租约，不把历史 `isDrawn` 伪装成预览首帧 fence；`nativeReady` 和 `nativeTakeover` 分别报告。

## 验证与交付

185 项核心回归、114 项模拟器管理器检查、356 项目标 DEX/元数据检查通过。新增回归覆盖解锁后 going-away 清零、1024 种原生接管条件组合、缺少预览证明时的原生接管，以及乱序回执。自有离屏生产图层探针验证 HOME 没有兜底镜像、目标切换撤销 HOME 直通、退出不释放系统壁纸句柄，同时保留 APP 渐变换源／取消检查。

APK 已安装且手机 SHA-256 一致。安装后四进程仍运行 0.2.21，需要一次用户重启加载新的系统框架。新版实际原生接管、桌面图标、应用露出和闪烁均未验收，测试通过不能替代这些视觉结果。没有扩大作用域、杀桌面或普通应用、自动重启或要求反复复现。
