# 0.2.8：底部优先区域、唤醒接管与客户端恢复候选

## 新功能

管理器的「底部解锁优先区域」提供启停、高度、宽度和水平位置。默认高度 15%、宽度 100%、居中；范围分别为 5–40%、20–100%、0–100%。越出屏幕的水平位置按边界限制。

嵌入式实时预览使用生产 `BottomGestureRegion` 的相同几何计算，拖动滑块立即刷新，也能按住试划并显示该序列属于优先区域还是原生区域。预览没有创建全屏浮窗。配置保存和现代 Remote Preferences 同步在松开滑块时进行；手势固定参数快照，在结束后采用新范围。

真实接管在 NotificationShadeWindowView 的原生门禁与 FalsingCollector 之后、ViewGroup 子视图分发之前进行。区域内 DOWN 及后续整个序列直接送入现有 `initDownStates` 和 `TouchHandler.handleTouch$1`，保留原生 tracking、速度、误触判定和认证交接。快捷按钮、长按和横向子视图不接收该序列。离开区域后继续持有原序列；失去接入资格时撤销运动但不向子视图发送半段事件。区域外保持既有处理。AOD、原生认证、编辑和控制中心门禁保留。

## 本轮现场与根因

0.2.7 已在 boot 137 的 SystemUI、system_server、壁纸和设置加载。用户完成亮屏第一划及半屏停留测试，明确反馈桌面图标始终不出现。

手势日志多次记录 DOWN 后被「原生锁屏隐藏动画正在运行」放弃，随后 UP 进入原生 `endMotionEvent` 的解锁动画。这是模块把视觉淡入状态错误当作输入禁区。0.2.8 删除该视觉状态拒绝条件，接受垂直拖动时使用原生 Folme cancel、alpha animator end 和 `cancelWakeupAnimations` 交接，不直接设置认证或唤醒完成标记。唤醒观察器和退出 doze 的原生回调提前捕获面板及准备场景。

目标原生高度更新在关闭时检测 `0 < height < 1` 并直接结束 mHeightAnimator。0.2.8 保留弹簧原始输出，仅将关闭动画的非最终原生采样下限设为 2px；最终帧仍为 0，非模块动画不受影响。回归测试重放现场高速释放参数。

半屏停留的 SurfaceFlinger 现场确认桌面 VRI 有实际缓冲区、alpha=1、全屏边界及完整可见祖先，负一屏附属窗口 alpha=0；锁屏镜像和区域模糊按覆盖高度裁切。框架客户端状态仍是 STARTED。这证明窗口准备改善，不能证明缓冲区内已经包含图标。

本机 MiuiHome APK 没有 DEX 类，使用 Rust/native 和 Flutter。二进制中有 Launcher onResume 和锁屏/解锁准备状态处理。因此，START 不足以恢复客户端内容是当前待验证的原因推断，不能从字符串或可见缓冲区得出图标已显示。

## 原生客户端恢复及边界

只在有效会话、原生允许解锁、完整锁屏覆盖提交、安全目标和 SystemUI 持有输入焦点时，调用选中目标的原生 `makeActiveIfNeeded`。同步调用内限定目标 Display 的 sleep 查询，不删除 sleep tokens、不改变电源/keyguard 状态、不移动任务，也不合成 USER_PRESENT；原生用户和 AppLock 检查仍执行。

记录实际 RESUMED 和 `activityResumedLocked` 客户端回执；就绪还要求窗口绘制与输入焦点。取消时只对模块恢复且仍处于 RESUMED 的目标调用原生 pause；已进入原生解锁则交接生命周期。焦点失去时撤销会话。

原生 RESUME 是否足以解除本机 Flutter 桌面内部视觉准备状态，需要下一次实际图标测试。认证、应用行为、回弹/AOD、帧时间与手感也不能由离线测试或隔离探针宣告通过。
