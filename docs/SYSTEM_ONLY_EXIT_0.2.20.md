# 0.2.20：收敛作用域、拆开控制请求和首帧证明

用户撤销普通应用 Hook。本轮仅删除本模块额外添加的作用域，SQLite 一致备份后删除实际存在的 133 项；原五项与其他模块配置保留。公开推荐作用域为 SystemUI、Settings、system、MiWallpaper。普通应用即使被旧框架缓存加载，入口也直接返回。客户端帧观察器与 JNI 均不打包；历史研究源码保留但不执行。

## 已确认的旧依赖

旧 `SystemUiHooks.finish()` 在 `showBouncer()` 原生解锁调用之前等待返回窗口呈现；`DismissalHandoff.consume()` 也要求已呈现帧。快划结束时返回窗口还未通过原生恢复/绘制，这条路径可能一直等待，五秒后回弹，导致重复划动。0.2.18 的实际回执还确认客户端观察器加载失败，不能继续依赖该路径。

## 当前交接

1. 一次有效上滑已释放且运动收起，独立消费原生控制请求；正在触摸、动画未停、取消、回弹均不能触发。
2. 框架核对同会话、递增手势请求以及实际完整保护层提交，返回准备 ACK；它不代表返回画面已就绪。
3. SystemUI 再核对原生认证资格，然后仅调用一次原生 `showBouncer()`。不修改认证标记，不向应用安装任何 Hook。
4. 框架从实际 `finishDrawing` 中消费新绘制事务，并核对 latch 与呈现 fence。空事务、历史已绘制状态、原生超时不能通过。
5. 返回窗口 Surface 重建使旧证明失效，但保留交接阶段。原生 `keyguardGoingAway` 重新布置实际窗口绘制请求，不让此前空回执耗尽退出阶段的尝试。
6. 原生隐藏 Shade 后，其 ViewRoot 可能停止绘制；独立镜像使用直接 SurfaceControl 提交，仍等待真实提交回调。可见 Shade 保持原有 on-draw 路径。
7. 已交出原生控制权后不因五秒超时重新锁手机。首帧、实际前景隐藏提交与原生返回目标/祖先层稳定可见全部满足，才释放覆盖。

取消请求使用会话与手势序号形成 tombstone；旧准备 ACK、旧 END、旧绘制、旧隐藏帧不能接管重新接手后的手势。已被原生接受的动画不随 `mCanDismissLockScreen` 清理而切回密码阻尼分支。

## 验证边界

- 176 项 JVM：保留运动测试，增加“只有原生解锁之后才产生首帧”的时序回归、取消/重新接手、乱序请求和 Surface 替换。
- 110 项管理器/状态/角色检查；普通应用作用域明确拒绝，框架/UI 版本必须匹配。
- 356 项目标 DEX/APK 检查；确认 APK 没有客户端观察器类、JNI，作用域四项及 SDK37 原生退出入口。
- 本机离屏事务回执检查，以及调用生产 `NativeWallpaperComposition.submit()` 的无 ViewRoot/隐藏窗口探针；提交回调通过。只创建自有离屏层，没有读取像素、录屏、触摸注入或操作前台应用。
- 安装/哈希、实际进程版本、真实交接和视觉效果分开报告。当前实现尚不能证明真实桌面/应用已即时透出，或黑底/闪烁已经消失。

旧客户端观察器仍可能驻留在尚未重启的进程中。一次设备重启加载新系统框架并退出旧驻留 Hook；脚本不自动重启设备。
