# 锁屏阶段人工验收

由用户在真机进行；自动脚本只安装、读取状态及帧数据。

## 启用前后

1. LSPosed 选择 SystemUI、Settings、系统框架 android 三个作用域。
2. 新增/更新框架适配后由用户重启手机。应用内重载仍只处理 SystemUI 与 Settings。
3. 确认管理器显示当前版本的 SystemUI 与 android 回执及已加载状态。
4. 打开系统锁屏设置，确认 Flyme 手感入口能显式进入管理器。
5. 对首次重载记录：请求是否成功、Root 是否获准、新 PID 是否出现。请求成功不能替代加载回执。

## 动作与预期

| 动作 | 要检查的结果 |
|---|---|
| 慢慢上拖再松手 | 内容跟手，未越过阈值时回弹，无位置跳变 |
| 慢拖越过阈值 | 原生允许退出时退出，需要认证时进入原生认证 |
| 短距离快速上滑 | 原生接受手势后按速度判定，误触过滤仍有效 |
| 拖动途中反向 | 当前位移连续，最后方向参与释放判定 |
| 回弹中重新接手 | 从当前位置继续，旧动画结束不结束新手势 |
| 系统取消触摸 | 原生取消后恢复，不残留裁切和位移 |
| 从桌面锁屏，上滑停住 | 桌面壁纸可见，锁屏景深背景与内容一起移动，无黑块或闪现 |
| 从普通应用锁屏，上滑停住 | 原生允许解锁时透出原本返回的真实应用窗口；安全窗口继续受限制 |
| 上滑露出后反向/回弹 | 锁屏重新覆盖，原生壁纸和应用可见性恢复，不残留场景 |
| 已露出时息屏或停用 | android 回执确认回滚；AOD 与后续锁屏正常 |
| PIN / 指纹 / 人脸 | 仍由原生认证，成功后继续原有规则，失败不越过锁屏 |
| 原生模糊 | 模糊回调计数增长，壁纸/窗口材质正常，无自制模糊层 |
| 修改高级参数 | 当前拖动和回弹保持原参数，下一次手势采用新参数 |
| 停用移植 | SystemUI 确认新配置，下一次手势原生处理 |
| AOD → 唤醒 → 锁屏 | AOD、亮屏、壁纸衔接正常，无残留属性 |
| 左右快捷页与锁屏编辑 | 保留原生手势和状态，不接管其动画 |
| 左右顶部下拉分区 | 通知区域和控制中心区域保持当前逻辑 |
| 控制中心 | 现有模块效果与交互继续保留 |
| 设置重载 | 重新打开设置后入口重新注入，无重复项 |

## 共存与性能

若出现冲突，记录所启用模块、其相关功能、具体动作、回执错误和出现时间。先确认重叠入口，再由用户选择停用哪些重叠功能。

采集实际手势前后刷新率与 `gfxinfo framestats`。锁屏、认证、模糊和回弹分别记录区间；只统计该区间新增帧。120Hz 的预算约 8.33ms，但必须按手机实际刷新率与帧截止时间评价，不能使用模拟器结果。

通知中心阶段在锁屏验收后继续；再检查展开/收起、卡片展开、回复、媒体控制、横滑及左右分区。
