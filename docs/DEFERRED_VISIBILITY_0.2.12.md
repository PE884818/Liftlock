# 0.2.12 壁纸显隐请求与持续位移

## 用户澄清及上一版结果

0.2.11 已在 boot 140 的 SystemUI 实际加载，多次执行等待原生前景隐藏帧提交的新路径，仍验收失败。用户明确描述：桌面壁纸先闪成模糊锁屏壁纸，随后文件夹背景采样错误画面；半屏按住时锁屏时钟持续跳动。不是图标或桌面客户端消失，也不归因为未加载。

## 壁纸交接

目标系统 `WallpaperWindowToken.updateWallpaperWindows()` / `setVisibility()` 在原生过渡期间可先更新 `mVisibleRequested`，而延迟提交客户端显隐。`isVisible()` 返回延迟中的客户端状态；这期间可以出现请求隐藏但客户端仍可见。

旧恢复助手在重挂锁屏源时读取 `isVisible()`。手机 SDK37 的自建离屏生产助手测试模拟原生请求隐藏、客户端显隐仍为真，并同时撤去锁屏覆盖。0.2.11 返回红色锁屏像素，证明确有该交接缺口；0.2.12 相同场景保持绿色桌面像素。

现在同一事务的重挂与显隐使用当前 `isVisibleRequested()`。反向请求显示、客户端仍隐藏的取消/AOD恢复也通过。没有改原生认证、壁纸 token 标志或文件夹模糊实现，HMC 封面和壁纸引擎保留。框架退出回执增加源 layer、requested/client 显隐，用于下一轮核对真实来源。

这证明生产恢复助手在原生延迟显隐条件下的行为；尚未证明该分支解释了真机每一次闪屏，也未直接读取厂商文件夹采样纹理。

## 持续位移

旧代码在每次高度回调、pre-draw 和角色应用前恢复上次 View 属性，再写回当前位移/透明度/裁切。新增测试对实际 View setter 记录显示：即便手指高度没有改变，整页仍反复写入原生位置与手势位置。旧实现因此不能保证两个绘制回调之间持续保持模块姿态。

现在 `LockscreenPose` 与 `WallpaperLayerPose` 持续保存原生基线和已持有值，直接更新下一帧；属性未变时不调用 setter。真正的原生属性变化仍作为新的基线，退出或角色移除才归还。高度回调和退出等待阶段不再每次归零。时间等内容继承整页位移；景深前景仍保持原来的优先级、父层级及屏幕位置，只随壁纸裁切淡出。

120 次静止帧的 root 位移、景深位置/alpha/clip 均无中间恢复写入；原生基线更新、释放恢复及原有软件像素测试通过。本轮再次启动的旧版真人采集没有取得对应半屏锁屏手势，因此尚未用真实屏幕把所有时钟跳动归因到这一条路径。新回执加入 nativeH/rootY/finger，下一轮核对实际运动和原生写入。
