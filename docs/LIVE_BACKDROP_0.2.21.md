# 0.2.21：实时桌面壁纸兜底

按用户最新选择：返回目标慢加载时，先以当前 HOME 壁纸完整遮住返回窗口；锁屏内容、景深透明度、锁屏壁纸裁切继续跟手。真实应用／桌面窗口的新帧呈现并且显隐链就绪后，约 180ms 渐变撤掉兜底壁纸。没有加入桌面或普通应用 Hook，也没有使用截图／静态桌面预览。

## 两份独立的证明

系统框架从已登记的 HOME 壁纸引擎中选择匹配客户端根、角色和当前绘制代次的输出。只有引擎 EGL 绘制、实际容器及祖先显示成立后，才创建独立实时镜像；其完整覆盖事务提交后，通过带会话和递增序号的回执报告 `backdropReady`。

`backdropReady` 只允许 LOCK 壁纸按当前手势进度裁切、淡出，不能代表返回窗口已加载，也不能完成原生交接。真实返回目标仍独立核对选中的 WindowState 身份、Surface 代次、真实新绘制、事务完成和呈现 fence。历史 `isDrawn` 保留用于诊断，不再在实际首帧证明成立后形成另一道旧状态门槛。

框架在真实返回画面就绪后启动渐变。最终 alpha=0 的事务已提交、原生目标及祖先显示、原生前景隐藏证明成立后，才结束覆盖。镜像换源保持当前透明度；取消或图层失效会使旧渐变回调失效。LOCK 镜像更换不撤销同一会话已提交的 HOME 兜底。

模糊高度跟随锁屏内容的实际运动输出，不再跟随“等待首帧而保持整屏覆盖”的壁纸高度。因此露出的桌面壁纸区域不会被这个锁屏模糊层覆盖；密码认证仍保留原生分支。没有修改普通应用自己的材质和模糊。

## 失败与边界

兜底未得到合格的 HOME 引擎输出时仍保持完整 LOCK 保护，不把未知输出当作就绪。渐变异步事务异常会停用本进程的可选兜底、尝试原子恢复 LOCK 保护并报告错误，避免异常逃出 system_server 的 Handler；不宣称所有底层服务故障都可无缝恢复。

这次增加的桌面失败回执独立保存在 `lastHomeReadiness`，后续 APP 或 END 回执不会覆盖它。这样不会用 APP 已呈现掩盖 HOME 首帧仍未就绪。

182 项 JVM、112 项模拟器管理器检查、356 项目标 DEX/元数据检查通过。实际 myron 的自有离屏生产图层探针覆盖：兜底与真实画面证明分离、渐变中换源、取消拒绝迟到回调和事务提交后释放；没有读取手机像素。空离屏事务的完成回调没有被当成应用首帧。

APK 已安装且手机哈希匹配。安装后四核心进程仍为 0.2.20 / boot148，需要一次用户重启加载框架、UI 和壁纸进程的新代码。新版真实回调、桌面图标、应用渐变、闪烁和手感均未验收，离屏验证不代表这些视觉结果。
