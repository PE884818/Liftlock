# 0.2.6 快划、提前准备与局部模糊

## 已捕获的失败

boot 136 的 0.2.5 已加载到 SystemUI、系统框架和壁纸进程。用户确认仍出现壁纸追赶和原生动画；`runtime-0.2.5-fast-trace.jsonl` 记录了 `p=0.696`、内容位移 `-792px`，但 `wallpaperP=1.0`、壁纸覆盖高度仍为 `2608`、`ready=false`。这是内容与壁纸呈现进度分离的直接证据。

现场还观察到返回 HOME、APP 已 STARTED 且绘制就绪，不能把所有失败归因于应用没启动。快速手势日志多次进入模块的统一释放和弹簧；日志采样不足以证明每次用户所见原生动画都来自某个绕过分支。源码另确认，原生动画结束清理可以先于模块最后一帧 pre-draw 提交，0.2.6 对此增加提交回执门槛。

## 实现

亮屏可交互时预热会话：先绑定并提交完整锁屏镜像，随后按原生认证资格请求实际返回窗口 START 和绘制。该步骤不会直接完成解锁。原生可解锁且窗口、祖先、客户端绘制和壁纸均就绪，才允许下方场景参与呈现。回弹与未拖动的按住结束后保留完整覆盖和准备结果。空闲预热只在绑定、认证资格或尺寸变化时提交，避免无变化时持续制造绘制事务。

`MotionFrame.withPresentationProgress` 对时间、通知、快捷方式、壁纸角色、镜像及局部模糊生成同一呈现进度，保留原始弹簧高度、速度和超出量。冷场景不再让内容先走、壁纸停住；就绪后整帧连续追赶。已经预热就绪的第一帧直接跟随触摸，不重置冷启动追赶。

原生 fling 结束通知被暂存，最后一帧通过 ViewRoot 的绘制事务提交回调后，才执行原生结束清理。认证消耗同样要求当前手势的提交回执；旧手势和取消回调不能授权新手势。`onAnimationEnd` 调用者解除编译内联，极短原生动画仍接入弹簧。

景深前景沿用 0.2.5 的壁纸角色：不随时间位移，透明度与镜像相同，裁切随覆盖高度变化，保留父节点和原生 Z 顺序。局部模糊仍采用澎湃 BackgroundBlurDrawable，屏幕区域为剩余锁屏高度。`NativeRegionalBlurLease` 只在当前窗口的过渡拥有模糊时抑制整窗/整张壁纸半径，保存最新原生意图并在认证、AOD、取消或退出时恢复。没有改写原始引擎的纹理缩放，也没有用静态桌面图片替换实际窗口。

## 进程兼容与验证

`unchanged-process-adapters-0.2.6.json` 将框架、壁纸、设置及协议共 16 个文件与已交付 0.2.5 源码逐字节比较，全部一致。因此本轮已运行的 0.2.5 系统框架与壁纸可继续使用，只重载 SystemUI。管理器显示真实版本并标注兼容；这一例外仅适用于当前 0.2.6 与指定的 0.2.5，不自动接受其他历史版本。

构建和 lint 通过；JVM 97 项、管理器 70 项、模拟器 Surface 合成 32 项、目标 DEX/元数据 273 项通过。myron 隔离探针验证原生 Drawable ABI、裁切、退出清理、景深角色回滚，以及当前 ViewRoot 的原生壁纸模糊借用和最新意图恢复。

上述探针是未注册窗口的 Root 隔离进程，手动提供位置回调，不能证明 SystemUI 的实际 RenderThread、真实合成像素、整窗 BlurUtils Hook 或用户手感。模拟器 SDK34 合成验证没有加载澎湃 Hook。ADB 回执采样不能解析所有快划帧；真实清晰透出、无闪烁、认证与 AOD 仍需手机实际手势确认。
