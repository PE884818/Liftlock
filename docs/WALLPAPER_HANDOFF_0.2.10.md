# 0.2.10 壁纸显隐与镜像代次交接

**最新真机结果：用户重启后 boot 140 的四进程均已加载 0.2.10 并触发手势，仍报告文件夹底板瞬间变灰，以及回弹/越界覆盖不足。本版本未验收通过；下方首次安装的“待重启”是历史状态。**

本轮针对已实际加载的 0.2.9 修复。用户最终澄清“闪黑”实际是文件夹模糊底板短暂变灰，图标仍显示；不再把这次现象归类为桌面图标被暂停或消失。

## 真实现场与代码根因

boot 139 的 SystemUI、system_server、MiWallpaper、Settings 都已加载 0.2.9，不能归因于旧进程未更新。用户自行锁屏/解锁，采集未对物理手机注入触摸、密码、指纹或重启。受控录屏最后一次解锁后可见桌面图标，后续静置也可见；在交接处逐帧看到：

- 实际 PTS 43.12514 秒：锁屏壁纸短暂回到桌面图标后面。
- 43.13172 秒：可见壁纸恢复桌面画面。
- 43.13808、43.14719 秒：图标仍在，文件夹底板使用了灰暗、带锁屏壁纸颜色的模糊取样。
- 43.15463 秒：文件夹底板恢复桌面壁纸的颜色。

这是采集视频的线性解码 PTS，不是每秒帧数或物理刷新率测量；旧稀疏拼图的请求取帧时间不能用于精确对齐。原始录屏、聊天画面、桌面截图、窗口日志均留在本地，不进入对应源码包。公开摘要见 `evidence/visual-observation-0.2.9.json`。

本机实际厂商源码链路是 `WallpaperWindowToken.setVisible()` 先更新原生客户端显隐，再通过 `WindowAnimator.addSurfaceVisibilityUpdate()` 排队提交 Surface 显隐。旧助手在另一笔事务里把已脱离合成的锁屏源重新挂回父层，未同步当前原生显隐位。隐藏事务尚未抵达 SurfaceFlinger 时，重新挂回的旧锁屏源会短暂显示；下一次原生 PassBlur 取样也会采到它。视频中的一帧背景回现及随后两帧文件夹取样异常与这个顺序相符；离屏生产助手回归也直接复现了重挂时的像素缺口。

另外两条确定的镜像代次缺陷也一并修正：原生暂时没有选中壁纸目标时不应撤掉有效覆盖；`WindowContainer` 同一 Java `SurfaceControl` 经 `copyFrom` 换了原生句柄后不能误判为旧生产者。

## 实现

`ServerWallpaperMirror` 对生产者持有独立、稳定的 SurfaceControl 句柄副本，按原生图层身份识别替换，原生容器的可变句柄不再作为旧镜像的身份依据。有效目标缺失时保留当前镜像。新镜像先隐藏，等待 SystemUI 全覆盖提交回执后才恢复和释放旧镜像/句柄；最多保留 8 个待交接代次，超出后由既有故障停用路径恢复原生。

归还生产者时，在同一笔事务中完成重挂、同步 `WallpaperWindowToken.isVisible()` 的当前原生值、移除镜像。既不回放手势前的显隐，也不修改锁屏、认证、Activity 或壁纸 token 的原生状态。只在提交回执后释放自持句柄；借来的原生句柄不由模块释放。取消/AOD 的当前原生 visible=true 同样同步，防止沿用上次解锁的隐藏位。

四个作用域保持原有配置。SystemUI 与框架要求 0.2.10 配对，未改动的壁纸/设置适配器允许已有 0.2.9。管理器重载前也会撤销已加载的 0.2.9 会话。没有更改文件夹材质、桌面自身动画、控制中心、运动默认值或底部优先区域。

## 验证边界

- 旧 0.2.9 交付 APK 执行生产恢复助手：模拟原生隐藏已排队但未提交，重挂后采到红色 LOCK，预期失败。
- 0.2.10 交付 APK 执行同一助手/场景：重挂后保持绿色 HOME，随后原生隐藏提交不改变像素，通过。
- 当前原生显示已更新但 Surface 位仍旧隐藏的反向场景恢复 LOCK，通过。
- 无目标保持旧覆盖、新覆盖提交前保留旧覆盖、提交后再退役、可变 Java 句柄换原生 Surface 后增加镜像代次，通过。
- 探针只使用自建 64×64 Surface、离屏 layer stack 100733，没有安装 Hook、改动真实窗口或操作输入。它证明生产助手的事务行为，不能单独证明实际文件夹模糊、AOD、认证或手感已通过。

证据：`evidence/scene-native-hide-regression-0.2.9-myron.txt`、`scene-restore-0.2.10-myron.txt`、`scene-replacement-regression-0.2.9-myron.txt`、`scene-source-copy-regression-myron.txt`。本轮 release/lint/签名通过，304 项目标 DEX 与元数据检查通过，SDK34 管理器 83 项通过。原生模糊的三个生产文件与 0.2.9 一致，没有用管理器或离屏结果代替真机验收。

0.2.10 已安装并核对手机文件哈希。安装后 boot 139 四进程仍运行 0.2.9，框架改动需要用户重启；本轮没有自动重启。重启后需核对实际加载的版本，再验证解锁后文件夹底板、锁屏到 AOD 交接和连续取消/解锁。真实灰块修复、AOD 与手感验收目前仍待确认。
