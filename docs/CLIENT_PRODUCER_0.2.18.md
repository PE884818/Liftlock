# 返回客户端新缓冲交付

**历史方案，已撤销。** 0.2.18 在 boot147 实际加载后仍失败，客户端观察器报告 `UnsatisfiedLinkError`。用户明确拒绝普通应用 Hook，0.2.20 已移除额外作用域，入口忽略普通应用，客户端类/JNI 不打包；改为原生退出和 WMS 实际绘制交接，见 [当前实现](SYSTEM_ONLY_EXIT_0.2.20.md)。下文仅记录研究经过，不能作为当前部署步骤。

## 已证实的失败

0.2.17 / boot146 四核心进程实际加载。29 个真实客户端 finishDrawing 全是空事务；27 个一次性处理器消耗，保留下一缓冲序号30次、重发18次仍无就绪。安装、作用域和重启不能解释这次失败。真实 `handleResized` 并未调用 fixture 使用的 setter，原先的 resize 标志覆盖推断撤回。

空绘制 ACK 并不包含实际缓冲的呈现证明；不能将其拒绝后持续占住完整覆盖作为正常实现。Android 17 的 WMS WindowState 容器与 `getClientViewRootSurface()` 是不同层，后者对应客户端 VRI 的实际绘制 Surface。

## 新接口

框架先准备受原生认证允许的返回窗口及完整覆盖，再用共享发送身份的显式广播请求具体客户端。请求带会话、绑定、真实 IWindow Binder、客户端 Surface ID 和加载版本。应用进程仅查找匹配 Binder 的 VRI，校验绘制 Surface，注册生产者监听，并在其原生 UI 线程请求一次完整新绘制。

生产者完成事件带帧号、latch 和呈现 fence。本模块复制 fence FD，在专用线程等待，不在 WM、UI、Binder 或渲染线程等待。只有本次绑定后 latch 的实际新帧和有效、已发信号的 fence 才回报；纯位置变换、空层及旧帧均不合格。观察器在完成、结束或五秒无回执时关闭；这个观察器寿命不充当“已经就绪”的替代证据。

框架核对共享的实际发送包名/UID、同一窗口 Binder、原生认证、当前窗口容器、当前客户端 Surface 和绑定，再推进原有 ScenePresentation / SceneReadiness。帧号独立于 WMS resize 序号。原有窗口显隐、祖先、RESUME、壁纸和镜像条件仍必须满足。

原生 `WindowToken.setClientVisible(true)` 可因缓存已为 true 而不派发；在所选窗口的准备阶段重发原生 `sendAppVisibilityToClients`，不伪造 Activity RESUME 或输入焦点。Native `unsetBuffer` 清除所选客户端缓冲时，在同一事务加完整覆盖，退役旧证明，提交后重新准备。invalidate 即递增绑定，迟到回执不能复活旧画面。

## 原生绑定边界

原生 SurfaceStats 是当前进程的 TransactionCompletedListener 回执。两进程自建实验确认，在框架进程注册不能接收别的进程的生产者缓冲。因此监听必须装在所选客户端，不能用单进程离屏成功来冒充框架接入成功。

C++ 只读取完成统计及 fence，不查询/采集任何像素、不创建真实屏幕窗口、不修改壁纸内容。现有 libgui 已驻留，由 ELF 符号表绑定，未修改链接命名空间，也未加载第二份厂商库。私有统计偏移与 Fence 布局只适用于固定的 myron 构建，Java 在加载前校验完整 libgui/libui SHA-256；不支持的构建拒绝初始化。

新帧观察器需 `com.miui.home` 和对应返回应用作用域。现有其他模块保持原配置。批量增加当前用户应用作用域前，使用 SQLite 一致备份；事务只插入本模块的 scope 行，不改 enabled、远程参数、其他模块、原有作用域或 APK 路径。新安装的应用仍需加入其作用域。客户端没有运动、布局、应用内容或桌面动画 Hook。

## 验证与尚未确认的结果

161 项 JVM、105 项管理器、356 项目标静态检查通过。使用最终打包原生库，自有离屏真实缓冲及 BLAST 帧1/帧2取得有效 fence，纯位置事务不合格；两进程实验在生产者进程监听并跨进程回报通过。没有录屏、截图、像素读取、触摸注入或要求反复划动。

这些结果证明缓冲回执及跨进程通道的基础机制，不证明真实锁屏和任意应用视觉已成功。实际新回调、桌面/应用透出、闪烁、等待和手感须在新框架与客户端加载后分别确认；不把探测时间当成设备解锁耗时或帧性能结论。
