# 0.3.5-miuix22：修复熄屏久了再亮屏时锁屏壁纸变黑、通知和快捷方式背景消失（需要重启手机）

**现象**：熄屏一段时间后再亮屏，锁屏通知、快捷方式的模糊背景不见了，有时锁屏壁纸整个变黑。

**原因**：亮屏后用只读的 `dumpsys SurfaceFlinger` 查看图层树，发现锁屏壁纸的图层（`WallpaperWindowToken#43`）不在显示树里，而是挂在 SurfaceFlinger 的根节点下，处于屏外状态。
- 模块在上滑场景中会临时把锁屏壁纸图层摘下来，解锁时再把它藏起来。之后的恢复可能把它留在已被销毁的过渡图层下，结果就成了屏外的孤儿图层。
- 系统框架只在窗口层级变化时才会重新挂载图层。如果下一次锁屏（比如熄屏较久后）没有经过会动到它的过渡动画，它就一直留在屏外。
- 后果：锁屏壁纸变黑；通知和快捷方式的背景要模糊它们后面的壁纸，后面没有壁纸，看起来背景就消失了。

**修复**：熄屏、亮屏和新的锁屏周期开始后，框架进程以系统窗口管理的模型为准做一次核对：
- 把每个壁纸图层放回窗口管理认为它应在的父节点下；
- 如果窗口管理希望它显示，就让它显示。
- 不会隐藏任何图层，隐藏仍由系统自己决定。
- 正在被原生过渡或动画持有的图层会跳过，稍后重试。
- 正在上滑时被摘下来的图层，以及解锁退场时被保留隐藏的图层，都不会动。

每次核对都会写进框架回执的日志（`wallpaper:reconcile`），诊断详情里能看到。

**说明**：只改了系统框架（stage16），**需要重启手机**。这次是通过读图层树和代码定位的，修复后还没有在熄屏较久的真实场景里确认过。

# 0.3.5-miuix18：兼容其他 HyperOS 3 / 4 版本（需要重启手机）

以前每个进程里有两百多处成员是按名字查找的，任何一处找不到，整个进程的适配都会退回原生。现在的做法分三部分：

- **多候选查找**：同一个成员在不同版本上可能长得不一样，现在每一种都会尝试。包括：
  - Android 15 和 17 的签名差异，例如 `keyguardGoingAway`、`startedWakingUp`、`ensureActivitiesVisible`；
  - 编译器加的编号，例如 `handleTouch$1`、`fling$1`；
  - 访问器方法，例如 `$$Nest$m`、`access$NNN`；
  - 匿名类和 Kotlin 回调对象，改为按结构识别。
- **核心与可选分开**：
  - 核心是跟手拖动和统一释放，缺了才退回原生。
  - 其余每一项都可以单独关掉，包括：壁纸跟随、解锁模糊层、区域模糊、底部圆角、退场保持、唤醒预备、壁纸缩放接管、底部解锁区域、通知层修复、认证页位置、解锁不闪锁屏壁纸、设置入口、晚加载桌面。
- **系统框架或壁纸进程整体用不了时**：
  - 框架没有回应，上滑后交给原生解锁动画完成，不会卡住或回弹。
  - 壁纸应用找不到它的引擎类，就直接跟踪系统的壁纸引擎来统计出帧。

管理器首页会显示「部分可用」，并列出没有生效的部分。诊断详情新增「兼容性」分组，右上角复制出来的诊断里带有完整的兼容报告，测试者可以直接发回来。

说明：OS3 和其他 OS4 版本都**没有拿实机或系统文件核对过**。这些回退是根据 AOSP 各版本已知的差异和结构识别写的，实际效果要看测试者的兼容报告。四个进程都有改动，**需要重启手机**。

- 修复祖先图层缓存按创建顺序删记录的错误。只回收不再需要的记录，保留每个活跃 Surface 的完整祖先链；使用弱句柄，并从真实 WindowContainer 刷新复制后的句柄，不强行保留已废弃的 native Surface。
- 返回目标选择同 UID、非全透明的 BASE_APPLICATION 主窗口，排除 Launcher 附属的搜索/负一屏窗口。仍检查整个 Activity 的安全窗口与原生认证资格。
- 捕获 `setVisibility` 和全部 `apply` 包装入口的事务提交回执，防止已编译的包装方法绕过最内层 Hook。清空或关闭的事务不再保留未提交记录。未知、隐藏或循环的祖先链仍不能报告就绪。
- 失败回弹先结束旧原生 fling，并清除重新接手偏移；零距离恢复也更新真实原生面板高度。诊断新增具体阻塞图层，不再只有一个 `ancestors=false`。
- 框架返回自身版本，SystemUI 不接受旧图层适配器的就绪回执。0.2.7 必须加载新的 system_server；管理器明确显示需重启。详见 [STUCK_SCENE_0.2.7.md](docs/STUCK_SCENE_0.2.7.md)。

## 沿用的 0.2.6 运动实现（该版本的历史兼容说明不适用于 0.2.7）

- 亮屏、可交互且具备原生解锁资格时提前准备实际返回目标。先提交完整锁屏覆盖，再请求返回应用或桌面绘制；准备就绪后，手指刚上滑即可使用当前真实画面。回弹保留准备状态；AOD、认证、锁屏退出与停用会撤销会话。
- 内容、壁纸、景深和模糊使用同一个呈现进度。冷场景暂未就绪时整张锁屏保持覆盖，物理高度与速度继续记录；就绪后一起连续接续。预热已就绪的手势直接跟手，不重新等待 120ms 的追赶动画。
- 拦截原生 fling 的结束清理，等模块最后一帧的绘制事务提交回执后，再完成原生清理与认证交接。极短原生动画也走统一弹簧；关键调用者解除编译内联，防止绕过入口。
- 澎湃原生模糊 Drawable 只覆盖锁屏剩余高度。手势合成期间暂借用当前窗口的整窗与整张壁纸模糊半径，退出时恢复最新原生请求；露出的返回画面不由该模糊层覆盖，密码界面仍由原生管理。
- 系统框架、壁纸、设置适配器及跨进程协议共 16 个文件与 0.2.5 源码逐字节一致。本次只需重载 SystemUI；管理器保留其他进程实际版本，并标注兼容，不要求再次重启。实现与证据边界见 [FAST_REVEAL_0.2.6.md](docs/FAST_REVEAL_0.2.6.md)。

## 沿用的 0.2.5 实现

- 时间、通知和快捷方式跟手移动。景深前景、背景及静态抠图按壁纸角色处理：抵消模块的祖先位移，与镜像共享透明度和屏幕裁切；保留原生父节点、Z 层级和景深遮挡关系。
- 触摸、原生高度和异步回执只更新状态，由同一个 pre-draw 回调提交内容、壁纸、景深及模糊帧。重新接手使用上次已呈现的高度。
- 返回窗口与桌面壁纸须等完整覆盖镜像提交回执后才借用可见性。仅按住不进入拖动或收起分支；同一绑定的短暂未就绪回执保持当前覆盖，反向拖动可增加覆盖；新会话或 Surface 代次重新建立覆盖。
- 镜像更换时在同一绘制事务隐藏旧容器、显示新容器，提交之后再释放旧句柄；失败与取消仍恢复原生场景。详情见 [DEPTH_SYNC_0.2.5.md](docs/DEPTH_SYNC_0.2.5.md)。
- 锁屏 WallpaperWindowToken 实时镜像单独裁切、淡出，继承原生引擎及 HyperMusicCover 当前封面；不平移原始壁纸。
- 删除手写 blur regions 的独立效果 Surface。改用澎湃 BackgroundBlurDrawable，由原生 RenderNode 回调、Aggregator 和 ViewRoot 按绘制帧提交屏幕坐标与裁切。模糊 sheet 的底边跟随锁屏覆盖高度，不随内容弹簧超出量漂移。
- AOD、认证和解锁交接时立即移除模糊 Drawable。镜像仍等待原始壁纸恢复提交的回执后清理。
- 框架恢复事务异步提交，回执等待 SurfaceFlinger 的提交回调；不在窗口锁内等待 apply(true)。电源状态在取得窗口锁之前采样；已显示的祖先层不重复提交 show。
- 管理器显示各进程加载版本、场景回执及最长场景处理时间；本版补齐之前漏传的该诊断字段。该值包括等待窗口锁，不代表屏幕帧时间。

返回窗口仅在原生已允许解锁时准备；还要求完整覆盖提交和 SystemUI 输入焦点，通过原生 RESUME 恢复客户端渲染。0.2.9 将 HOME 的 RESUME 推迟至有效上滑。真实返回应用自己的绘制是就绪条件，桌面壁纸 swap 不能替代应用。默认运动参数：刚度 200，展开阻尼 0.81，收起阻尼 0.95；实际原生退出进度与手指进度分开处理。

## 启用与恢复

LSPosed 作用域为 `com.android.systemui`、`com.android.settings`、`system`、`com.miui.miwallpaper`。首次新增作用域或框架代码更新需要用户重启手机；管理器可重载 SystemUI、设置和壁纸。0.2.10 的框架代码已变更，安装后需要重启，确认 SystemUI 与系统框架均显示 0.2.10。旧壁纸/设置适配器可兼容，旧框架不兼容。新增作用域和安装成功不等于实际效果通过。

管理器可持久关闭模块。需要卸载时执行 `adb -s <真实手机序列号> uninstall com.zhuanz.flymemotion`，然后重启手机恢复已注入进程。模块不自动重启手机或执行认证、手势。
